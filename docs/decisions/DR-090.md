# DR-090: Managed prose is judged from the consumer's vantage

> **Born `proposed` per DR-029** — acceptance is a separate human act
> (*MinSpec: Accept ADR*). This record's live status is its frontmatter `status:`
> field, not this note.

## Context

`MANAGED_REGION_TEMPLATES` (`packages/minspec/src/lib/template-registry.ts:2076`) is the
set of files MinSpec scaffolds byte-for-byte into every repo that inits it. The bytes are
held identical by construction: the CI-review stack is generated from this repo's own
working files (`scripts/gen-ci-templates.mjs`), and the portability suite in
`packages/minspec/tests/managed-region-templates.test.ts:378` asserts the embedded copy
equals the on-disk source exactly.

That guarantee has a consequence nobody wrote down: **a false sentence in a managed file
cannot be corrected downstream.** An adopter who fixes the wording drifts from the
template, and the next *Refresh Harness Files* overwrites the fix. The only place the
sentence can be repaired is here.

#1108 was filed after the skeptic voter on AIClarityAU/sealbox#32 read one such sentence.
`scripts/hooks/canonical.py:4-7` — a managed template
(`template-registry.ts:2008`) — tells its reader that the file is a "Byte-for-byte twin of
`packages/shared/src/canonical.ts`", that the PreToolUse gate `spec-gate.py` imports it,
and that "INV-2 (the corpus-parity test) asserts this twin and the Node module produce
byte-identical output over every spec in `specs/`". All three are true in
`AIClarityAU/minspec`. In a repo that merely consumes the harness, the Node module is
absent, `spec-gate.py` is not in the managed set (grep: no `spec-gate` entry in
`template-registry.ts`), and no corpus-parity test exists — so the docstring promises a
guard that is not there.

### It is a class, not a typo — measured, not assumed

Sweeping the shipped content of the managed set for path references that no managed
template scaffolds (grep over the on-disk sources, 2026-09-02):

| Managed file | Line | Upstream-only claim |
|---|---|---|
| `scripts/hooks/canonical.py` | 4-7 | Node twin, `spec-gate.py`, the INV-2 corpus-parity test |
| `scripts/roles/reviewer.md` | 34-40 | `scripts/roles/vendor/*`, `scripts/sync-agency-agents.sh`, `vendor/agency-agents/…` |
| `scripts/roles/security.md` | 34-40 | same vendor-provenance block |
| `scripts/roles/architect.md` | 34-40 | same vendor-provenance block |
| `scripts/roles/skeptic.md` | 52 | `testing/testing-reality-checker.md` |
| `scripts/lib/agent-context.sh` | 61 | "Enforced by `packages/minspec/tests/agent-context-slim.test.ts`" |
| `.github/workflows/docs-lane.yml` | 50-52 | byte-identity with `scripts/auto-merge-gate.ts`, enforced by `packages/minspec/tests/outward-docs-exclusion.test.ts` |

Two of these assert **coverage** ("enforced by", "asserts") that the receiving repo does
not have, which is the worst shape: the reader stops looking for a guard because the file
told them one exists.

### The precedent, and why it is not the answer on its own

#1486 already hit this once, on `.github/workflows/ai-review.yml`, and fixed it by
rewriting the offending comment block on the way out —
`localizeMachineryPathsComment` (`template-registry.ts:1883`), replacement text at
`:1845`, tripwire on the upstream wording at `:1834`, gated by
`packages/minspec/tests/machinery-comment-localization.test.ts`. It is a good repair and
this record keeps it. What it did not do is generalise: it is one hand-written rewrite
for one block in one file, discovered by a human reading a downstream PR. Six further
instances survived it, which is the measurement above.

This is the same drift shape as `managed-script-dependencies` (#1098) and #1103: the
enumeration is right in isolation and wrong in aggregate, and *"the author must remember"*
is the rule that eventually is not remembered (`.minspec/constitution.md` — enforce, don't
trust the model).

## Decision

### 1. Managed prose is part of the shipped artifact, and is judged from the consumer's vantage

A comment, docstring or paragraph inside a managed file is not commentary about MinSpec's
repo that happens to travel — it is text MinSpec publishes into someone else's repo under
their filename. The standard it is held to is the product standard, not a code-comment
standard: **every factual claim in a managed file's shipped bytes must hold in every repo
that receives them.**

### 2. Attribution, not deletion, is the default repair

An upstream fact may be stated, provided the sentence names whose repo it is about. "the
minspec repo's corpus-parity test asserts …" is true everywhere; "INV-2 asserts …" is
false everywhere but here. Attribution is preferred over deleting the fact, because the
fact is usually the useful part — a consumer who knows the parity test exists upstream
knows why the file must not be hand-edited.

### 3. The gate reads the SHIPPED bytes, and has no exception register

A test (`managed-prose-vantage`, specified by SPEC-066) runs over
`renderManagedFile(tpl)` — the bytes an adopter actually receives, i.e. **after** any
`localize` rewrite — and fails when a path-shaped token in that text names a file the
managed set does not itself put in the adopter's repo, unless the surrounding comment
block or paragraph attributes it (case-insensitive `minspec(?:'s own)? repo`).

Two properties are load-bearing:

- **The "universal" set is derived, never enumerated.** It is the file list produced by
  actually scaffolding into an empty directory (`scaffold()` + `generateHarnessFiles()`
  with every tool detected), exactly as #1098's runtime half does. An enumeration here
  would re-import the drift the gate exists to catch.
- **There is no allowlist.** The only way to silence the gate is to write the attributing
  words, which is also the fix. An exception table would let an author silence the gate
  without repairing the sentence, and would itself rot.

### 4. `localize` is promoted from a one-off to a registry field

Where the upstream wording must stay upstream — long explanatory blocks that would be
noise in an adopter's repo — the repair stays #1486's: rewrite the block on the way out.
That capability becomes an optional `localize?: (src: string) => string` on
`ManagedRegionTemplate`, read by the portability suite from the registry instead of from
the hand-kept `CI_STACK` table in `managed-region-templates.test.ts:317` (a second
enumeration of the same set, which can drift from it).

Every `localize` must keep #1486's two safety properties: it throws rather than no-ops
when it cannot find its block, and it re-checks that the upstream string is gone from its
own output.

### 5. The rule is stated where the reviewers will read it

The vantage rule goes into the shipped review-role files (`scripts/roles/skeptic.md` and
`scripts/roles/architect.md`), which are themselves managed — so the standard travels to
every repo whose PRs those voters review, and the human who caught #1108 by hand has a
written basis rather than an instinct.

## Consequences

**What is bought.** The class becomes machine-detectable at PR time rather than at
downstream-review time, and the detection is a set difference against a *derived* set, so
adding a managed file that references an unscaffolded sibling fails immediately.

**Accepted cost 1 — managed prose gets longer and slightly stilted.** "the minspec repo's
corpus-parity test" is four words more than "INV-2". Every managed file pays this, forever.
Judged worth it: this repo already ranks a false claim as its worst defect (CLAUDE.md
Evidence Discipline), and the tax falls only on sentences that name an upstream artifact.

**Accepted cost 2 — false positives are possible and are paid in wording.** A path token
used as illustration (`docs/decisions/DR-NNN.md`) or an environmental file the scaffolder
does not create can trip the gate. SPEC-066 narrows the token grammar (placeholder-bearing
paths excluded; bare `.md` filenames excluded), but a residual false positive is resolved
by rewording, never by an exception entry. That is deliberate: a gate with an escape hatch
becomes an escape hatch.

**The residual, stated plainly: a claim with no path token is not detected.** "INV-2 (the
corpus-parity test) asserts …" names no file, and `canonical.py:6-7` is exactly that
sentence. The gate would catch that line only via the `packages/shared/src/canonical.ts`
reference two lines above it. So the mechanism raises the floor; it does not close the
class. §5 (the reviewer instruction) and the human repairs in SPEC-066 cover the rest, and
this record does not claim more than that. A prose-claim detector — an LLM voter asked one
question, "is every sentence here true in a repo that is not minspec?" — is the obvious
next step and is deliberately NOT decided here: it would put a non-deterministic judge on a
blocking path, which needs its own record.

**Not reversible in under a day, which is why this is a DR.** Once the attributed wording
ships, it is in every adopter's working tree, and the words come back only through their
next harness refresh.

## Alternatives rejected

- **Author discipline alone (#1108's option 1).** It is the fix for the seven known
  instances and it is applied — but as the standing rule it is the shape that produced the
  bug: #1486 taught exactly this lesson on one file, and the six others measured above
  shipped anyway.
- **A per-file `localize` for every instance.** Correct but disproportionate — four role
  files would each carry a bespoke rewrite plus tripwire plus test to remove one provenance
  paragraph, when one attributing clause is true and costs nothing.
- **An allowlist of sanctioned upstream references.** Rejected in §3: it lets the gate be
  silenced without the sentence being fixed, and the table drifts.
- **Strip all upstream references from managed prose.** Loses genuinely useful information
  (why this file must not be edited by hand) and is unenforceable — the next author writes
  a new one.
- **Ship a documentation URL instead of the explanation.** Violates the offline-first
  invariant in spirit: the adopter's copy stops being self-describing, and a dead link is a
  false signpost with extra steps.
